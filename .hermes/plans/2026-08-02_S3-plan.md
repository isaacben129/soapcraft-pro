# S3 — Plan: SoapCraft Pro Build Tasks

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Convert the 13-task build order into actionable kanban manifest (`tasks.json`) and GitHub issue tracking (`gh_ids.json`), ready for S4 parallel build execution.

**Architecture:** JSON-based task manifest with wave ordering, dependency chains, UX task flags, and TDD acceptance criteria. gh_ids.json is a placeholder mapping — IDs populated once GitHub repo is created.

**Tech Stack:** Next.js 16.2.10, PostgreSQL (Neon/Supabase), Tailwind CSS 4.x, shadcn/ui, OpenRouter API, NextAuth.js, Vercel.

---

## Wave 1 — Foundation (T1–T4)

### T1: Onboarding flow + experience assessment quiz
- **Objective:** First user-facing screen — 3-step quiz that sets up the user's experience level and goal.
- **Files:** `components/onboarding/`, `lib/onboarding/`
- **UX:** 3-step quiz with contextual chips (not a tutorial). App Life Spec §3 first-use guidance.
- **TDD:** quiz renders → user selects → state persists → next screen

### T2: Ingredient database + SAP calculation engine
- **Objective:** Safety-critical foundation. Relational ingredient DB with SAP values, deterministic calculation engine validated against SoapCalc.
- **Files:** `lib/calculations/`, `db/schema.ts`, `db/migrations/`
- **UX:** Instant calculation results (< 100ms), validation warnings. App Life Spec moment of truth.
- **TDD:** input oils + percentages → correct lye + water output → matches SoapCalc for same inputs

### T3: Recipe Builder — core form + calculation display
- **Objective:** Recipe creation form with oil selection, percentage blending, property ranges, warnings panel. Signature interaction (calculation reveal).
- **Files:** `components/recipe-builder/`, `app/recipes/`
- **UX:** Oil selection with SAP values, property ranges shown, warnings panel. Signature interaction: calculation reveal.
- **TDD:** select oils → set percentages → calculate → save → load saved recipe
- **Depends on:** T2

### T4: Batch Log — input logging + Making Mode (guided, not hands-free)
- **Objective:** Batch creation form auto-populated from recipe. Making Mode for CP only (HP/MP get simplified log). Safety checklist before starting.
- **Files:** `components/batch-log/`, `app/batches/`
- **UX:** Form auto-populates from recipe, large tap targets, persistent timers. App Life Spec: preserve user input on error.
- **TDD:** create batch → log inputs → save → list batches
- **Depends on:** T3

## Wave 2 — Core Features (T5–T8)

### T5: Cure Tracker — estimated windows + observation logging
- **Objective:** Tracks cure progress with honest estimated windows. Users log pH, hardness, observations. User marks batch complete.
- **Files:** `components/cure-tracker/`, `app/cure/`
- **UX:** Honest progress state (not fake completion), estimated window not declaration.
- **TDD:** log cure date → track days → log pH/hardness → user marks complete

### T6: Costing — cost per batch + cost per bar
- **Objective:** Real-time cost calculation as inputs change. Ingredient cost catalogue management. Margin visualization.
- **Files:** `components/costing/`, `app/costing/`
- **UX:** Real-time cost update as inputs change, clear margin visualization. App Life Spec: success feedback — proportionate.
- **TDD:** input costs → calculate per-bar → show target price → save

### T7: Recipe Library — browse + search + filter + save
- **Objective:** Curated + personal recipe library. Search, filter, save, rate. Part of Recipe Builder module (shared infrastructure).
- **Files:** `components/recipe-library/`, `app/library/`
- **UX:** Card layout with property ranges, tag filtering, curated + personal. Empty state handling.
- **TDD:** list recipes → filter → search → save → view details
- **Depends on:** T3

### T8: Free tier (calculator + 3 recipes + 1 active batch)
- **Objective:** Free tier gates with clear upgrade prompt. Never blocks core functionality. Existing recipes/batches remain viewable/editable.
- **Files:** `lib/auth/`, `components/subscription/`
- **UX:** Clear upgrade prompt (modal, not blocking). App Life Spec: empty state handling.
- **TDD:** free features work → upgrade CTA appears → paid features gated
- **Depends on:** T1, T3
