# SoapCraft Pro AI Operating Contract (Legacy v1 — Traffic-First Era)

> **Status: Superseded** — Moved to legacy for audit only. See `product/AI-OPERATING-CONTRACT.md` for the current anonymous-first utility hub version.

## Purpose

SoapCraft Pro was operated as an agent-owned engineering system. The agent carried implementation, verification, maintenance, evidence collection, and release preparation. Isaac made the narrow human decisions requiring domain judgment, safety judgment, commercial judgment, or an explicit external side effect.

## Goal metric

Advance SoapCraft Pro toward `RELEASE_ACCEPTED` without publishing unverified chemistry or claiming evidence not collected at the real boundary.

## Agent ownership

The agent owned repository reconnaissance, implementation, chemistry data-model repairs, tests, typechecks, lint, bounded production-build attempts, acceptance audits, browser and deployed verification, evidence capture, and maintenance.

## Human ownership

Isaac decided chemistry values, ranges, source quality, formula findings, launch scope changes, payments/CRM/accounts/cloud sync/subscriptions, production deployment, and safety/legal/commercial actions.

## Chemistry boundary

The current specialist review was `APPROVE WITH CHANGES`. The current single-value dataset must not ship unchanged.

Required chemistry work included: preserve standards-based min/max ranges and provenance, remove the coconut value of `0.273` as approved ordinary-coconut, model oil subtypes, add traceable nominal computational values, update NaOH molecular weights, add NaOH purity correction, add independent hand-calculated fixtures, and keep public chemistry fail-closed.

## Launch boundary

Initial launch was anonymous-first and free. Deferred items included payments, CRM/email capture, subscriptions, accounts/cloud sync, advanced workspace features, and final logo/brand-mark/photography/motion-design work.

## Verification standard

Passing TypeScript or Vitest did not prove deployed usability. Only a fresh independent acceptance audit with boundary-compatible evidence could produce `RELEASE_ACCEPTED`. A hung or timed-out production build was `BUILD_UNVERIFIED`.

## External side-effect rule

No production deployment, public post, payment action, account creation, database provisioning, or other irreversible external action could occur without explicit Isaac approval in the active session.

## Maintenance loop

At each steward run, the agent inspected git state, read this contract and related review packets, identified the highest-leverage unblocked repair, implemented it, ran tests, and committed only verified local work.
